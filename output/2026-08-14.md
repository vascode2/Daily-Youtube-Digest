**핵심 요약**
Oxylabs의 Patricija Žemaitytė는 개발 환경에서 작동하는 시스템과 실제 현실에서 살아남는 시스템의 격차를 극명한 사례들을 통해 설명합니다. 그녀는 1초 미만의 검색 API 재구축 과정에서 겪은 실시간 차단 문제와 대규모 비디오 API 확장, 그리고 초당 6만 건의 요청을 처리하기 위한 부하 테스트 과정을 공유합니다. 이를 통해 AI 시대를 뒷받침하는 웹 데이터 인프라는 한 번 구축하고 끝나는 것이 아니라 지속적으로 적응해야 하는 비즈니스임을 강조합니다.

1. **실제 현실과 개발 환경의 극명한 차이**
   - 개발 환경과 테스트를 완벽히 통과한 1초 미만 응답 속도의 검색 API가 실제 고객 시연 도중 심각하게 차단되는 상황을 겪으며 현실의 가혹함을 확인했습니다.
   - 느리고 비용이 많이 드는 브라우저 환경에서 레이아웃, 파서, 세션, 프록시 전반의 지연 시간을 극도로 줄여 평균 응답 속도를 4초에서 550밀리초로 단축했습니다.

2. **예측 불가능하게 확장되는 비디오 API 요구사항**
   - 한 달에 최소 5페타바이트(PB)의 데이터 처리를 요구하는 비디오 API 프로젝트를 2주의 촉박한 기한 내에 시작했습니다.
   - 단순한 자막 추출 요청에서 시작해 검색, 메타데이터 추출로 요구사항이 계속 확장되었으며, 고객은 비용 지불 없이 이미 30페타바이트의 데이터를 수집했습니다.

3. **초당 6만 건 요청 처리를 위한 언블로커 확장**
   - 언블로커(unblocker) 시스템의 처리 용량을 초당 1만 건에서 6만 건으로 확장하는 과정에서 부하 테스트 중 2만 건 부근에서 한계에 봉착했습니다.
   - 대규모 트래픽 상황에서는 가상 트래픽을 생성하는 것보다, 원격 측정(telemetry) 데이터 자체가 시스템 부하의 일부가 되기 때문에 측정값의 신뢰성을 확보하는 것이 진짜 난제였습니다.

4. **끊임없이 적응해야 하는 인프라 비즈니스의 본질**
   - 웹 데이터 인프라 구축은 한 번 완성하고 끝나는 프로젝트가 아니며, 끊임없이 변화하는 웹 환경과 차단 정책에 맞서 영원히 적응해 나가야 합니다.

## [에이전틱 AI를 위한 CaaS(Context-as-a-Service)의 부상 — Omer Primor, Bright Data](https://www.youtube.com/watch?v=Ot4OPrPH4xY)

**한 줄 인사이트**
💡 1만 5,000번의 쿼리를 넘어서면 컨텍스트를 대여하는 것보다 직접 파이프라인을 구축해 소유하는 것이 비용 면에서 더 유리해집니다.

**핵심 요약**
오머 프리모르는 웹 데이터의 빠른 감가상각과 반복 쿼리의 비용 구조를 분석하며, 서비스형 컨텍스트(CaaS) 대여 방식의 한계를 지적합니다. 그는 자체 스크래퍼 파이프라인 구축 비용과 외부 벤더 이용 비용을 비교하여 비용 역전 현상이 발생하는 지점을 명확히 제시합니다.

1. **웹 데이터의 빠른 감가상각**
   - 소셜 콘텐츠는 하루 만에, 뉴스·금융·소매 데이터는 30일 이내에 효력을 잃어버리므로 컨텍스트는 일회성 스냅샷이 될 수 없습니다.
   - 반복되는 쿼리는 내용이 변하지 않아도 매번 동일한 비용이 발생하기 때문에, 팀들은 결국 조사 주기를 줄이거나 범위를 축소하는 방식으로 대응하게 됩니다.

2. **CaaS 벤더의 커버리지 한계**
   - 전용 컨텍스트 벤더들은 이미 보유하고 있는 데이터 범위 안에서만 답변할 수 있어, 예상치 못한 질문에 대해서는 아예 답변을 제공하지 못하는 한계를 보였습니다.
   - 이로 인해 전용 벤더들이 오히려 일반 검색보다 낮은 커버리지 점수를 기록하는 의외의 결과가 나타났습니다.

3. **비용 역전이 발생하는 티핑 포인트**
   - 1주일 분량의 셋업 비용을 5,000달러로 잡고 직접 스크래퍼 파이프라인을 구축했을 때, 1만 5,000개의 엔티티 쿼리를 넘어서는 지점에서 대여 비용보다 저렴해집니다.
   - 파이프라인을 소유하면 초기 비용을 지불한 후 사후 검색 비용이 사실상 무료가 되므로, 장기적으로는 소유하는 구조가 훨씬 유리합니다.

## [From RL to IRL — Gaurav Mishra, Amazon AGI Lab](https://www.youtube.com/watch?v=Cc0_nyxROBA)

**한 줄 인사이트**
💡 가우라브 미슈라는 현실 세계의 브라우저 환경에서 AI 에이전트가 직면하는 한계를 짚으며, 가상 환경을 넘어선 강화학습(IRL) 성공을 위해 에러 복구 능력과 프로세스 보상 모델의 중요성을 강조합니다.

**핵심 요약**
Amazon AGI Lab의 가우라브 미슈라(Gaurav Mishra)가 실제 웹 환경에서 에이전트가 겪는 시행착오와 해결책을 발표합니다. 그는 가상 게임 환경과 달리 현실의 웹은 부분적 관측 가능성, 비가역적 행동, 만료되는 자격 증명 등으로 가득 차 있다고 분석합니다. 이에 따라 인프라 초기화 대신 에이전트 스스로 복구 능력을 기르는 '비행 학교' 방식의 훈련과 프로세스 보상 모델 도입을 대안으로 제시합니다.

1. **현실 세계 웹 환경의 치명적인 한계**
   - 에이전트는 지출 결의서 작성 중 로그아웃되자 비밀번호를 임의로 추측하다 계정을 잠그거나, 실제 제출 버튼으로 위장한 스폰서 광고를 클릭해 개인정보를 입력하는 치명적인 실패를 겪습니다.
   - DOM 구조는 이미지 속 텍스트를 누락하고 스크린샷은 스크롤 영역을 놓치는 등 관측이 불완전하며, 자격 증명 만료와 비가역적 행동이 에이전트를 가로막습니다.

2. **시험이 아닌 비행 학교 방식의 훈련**
   - 레이아웃 변화, 느린 로딩, 팝업, 포커스 가로채기, 만료된 탭이 가득한 샌드박스 환경에서 에이전트를 훈련해야 합니다.
   - 에이전트가 새로고침, 역추적, 대기, 에스컬레이션 등의 회복 조치를 인프라 리셋이 아닌 네이티브 모델 액션으로 직접 수행하도록 가르칩니다.

3. **프로세스 보상 모델과 캘리브레이션된 신뢰도**
   - 최종 결과만 채점하는 대신 위험한 경로에 있는 단계를 직접 벌하는 프로세스 보상 모델을 적용합니다.
   - 행동의 승인 여부, 가역성, 가시성을 사전에 판단하는 캘리브레이션된 신뢰도를 통해 모델이 스스로 통제권을 반환하도록 유도합니다.

3. **작업 환경과 툴의 전환**

**핵심 요약**

1. **학벌과 행복의 상관관계**
   - 서울대 등 명문대 진학이 인생의 최종적인 행복을 보장해주지 않으며, 오히려 기대감과 현실 사이의 괴리에서 오는 공허함이 클 수 있습니다.
   - 외부의 인정이나 타이틀 중심의 삶에서 벗어나 자신만의 가치관을 세우는 것이 진정한 만족의 시작점입니다.

2. **성공의 기준 재정립**

   - 타인의 시선을 의식한 성취보다 일상 속 소소한 성취와 내면의 평온함이 행복의 지속성을 높여줍니다.

3. **내면의 만족과 성장**
   - 끊임없는 경쟁 속에서 타인과 비교하기보다는 자신의 고유한 속도에 맞춰 살아가는 지혜가 필요합니다.
