## [I Made a Fruit Fly Review My Code - Nick Nisi, WorkOS](https://www.youtube.com/watch?v=geMAe-PLJF4)

**한 줄 인사이트**
💡 코드 생성 속도가 폭발한 지금은 사람 리뷰어가 병목이므로, 위험한 PR만 사람에게 올리고 나머지는 스크린샷·스모크 테스트 같은 증거로 대체해야 한다는 주장이다.

**핵심 요약**
WorkOS에서 개발자·에이전트 경험을 이끄는 Nick Nisi는 AI 덕분에 코드가 어느 때보다 빨리 쓰이면서 사람 리뷰어가 병목이 되었다고 말한다. 그는 이를 보여주기 위해 뉴런 전체 스캔으로 만든 초파리 뇌 시뮬레이션을 코드 리뷰에 연결하는 실험을 하고, 청중과 라이브 게임까지 진행한다. 마지막에는 위험한 PR만 사람에게 넘기는 현실적인 리뷰 체계를 제안한다.

1. **사람 리뷰어가 병목이다**
   - 코드 작성 속도가 빨라진 만큼 리뷰 수요도 늘었지만 사람의 리뷰 용량은 그대로라는 문제의식에서 출발한다.
   - '버그'라는 단어의 유래를 소개하며, 벌레로 버그를 찾는다는 실험의 도입부를 만든다.

2. **초파리 뇌를 코드 리뷰에 연결하다**
   - AI가 각 코드 변경을 문자 그대로의 '코드 냄새(code smell)'로 바꿔 초파리 뇌 시뮬레이션에 입력한다.
   - 설탕(보상)과 쓴맛(벌)으로 좋은 코드와 나쁜 코드의 맛을 학습시키며, 테스트에서 약 88% 정확도를 보였다.

3. **라이브 게임과 실제 PR 시험**
   - '초파리보다 똑똑한가?' 게임으로 청중이 초파리와 직접 겨루고, 실제 풀 리퀘스트에도 적용해 본다.
   - 초파리가 실제로 의미 있는지 묻고, 사람만 아는 '왜'라는 맥락이 남는다고 짚는다.

4. **위험한 리뷰만 사람에게 올린다**
   - 팀의 리뷰 스킬, 분류기(classifier), 자동 리뷰어를 조합해 위험한 PR만 사람에게 에스컬레이션한다.
   - 리뷰 자체보다 스크린샷, 스모크 테스트 같은 동작 증거로 신뢰를 확보하는 방향을 제시한다.
