**핵심 요약**

   - 전파 대신 레이저를 사용하여 우주 공간에서 대용량 데이터를 손실 없이 초고속으로 전송하는 백본망을 구축했습니다.
2. **초정밀 레이저 정렬을 위한 PAT 기술**
   - 빠르게 움직이는 위성 간에 좁은 레이저 빔을 정확히 맞추기 위해 초정밀 정렬 및 추적 기술인 PAT(Positive Amplification Technology)를 적용했습니다.

**핵심 요약**
Modal의 Nan Jiang은 대규모 강화학습(RL) 모델을 여러 데이터센터에 분산된 GPU 자원에서 효율적으로 실행하기 위한 새로운 접근법을 제시합니다. 그는 연속적인 학습 단계에서 실제로 변경되는 가중치가 1% 미만이라는 점에 착안하여, 무거운 전체 체크포인트 대신 손실 없는 패치만을 전송하는 동기화 메커니즘을 제안합니다. 이를 통해 초고속 네트워크 인프라가 없는 이종 클라우드 환경에서도 지연 시간 없이 탄력적인 롤아웃 플릿을 운영할 수 있음을 증명합니다.

1. **기존 RL 롤아웃 동기화의 한계**
   - 프론티어급 모델의 체크포인트 크기는 약 500GB에 달해, 이를 다른 지역의 롤아웃 플릿으로 전송하는 데 수 분에서 수 시간이 소요되어 실시간 가중치 업데이트가 불가능합니다.
   - 이로 인해 기존에는 학습 클러스터 내부의 초고속 네트워크 환경 안에서만 롤아웃 엔진을 함께 실행해야 하는 물리적 제약이 존재했습니다.

2. **아담 흡수(Adam Absorption) 현상의 발견**
   - 연속된 학습 단계에서 그래디언트 자체는 조밀하게 발생하지만, 미세한 아담 스텝(Adam step) 크기가 BF16 등 하위 정밀도 서빙 포맷의 반올림 경계를 넘지 못해 실제 출력 가중치는 거의 변하지 않습니다.
   - 실제로 GLM 4.7 Air 모델을 FP8 포맷으로 서빙하는 내부 테스트 결과, 첫 단계에서 단 0.15%의 가중치만 변경되었으며 이후에는 약 0.05% 수준으로 수렴했습니다.

3. **Stitch를 통한 무손실 패치 동기화**
   - Modal이 개발한 'Stitch' 아키텍처는 500GB 크기의 전체 체크포인트 대신, 비트 단위로 동일하게 복원 가능한 약 500MB 크기의 무손실 패치만을 전송합니다.
   - 사이드카(Sidecar) 프로세스를 통해 각 롤아웃 엔진이 최신 버전을 인지하도록 설계하여, 전송 데이터양을 99.9% 절감하고 동기화 속도를 초 단위로 단축했습니다.

4. **분산된 이종 GPU 자원의 탄력적 활용**
   - 패치 단위 동기화를 통해 롤아웃 플릿이 더 이상 학습 클러스터와 동일한 고속 패브릭 네트워크에 묶여 있을 필요가 없어집니다.
   - 이를 통해 여러 지역과 다양한 클라우드 제공업체에 흩어져 있는 유휴 GPU 인프라를 하나의 거대한 탄력적 롤아웃 플릿으로 통합하여 운영할 수 있습니다.

## [Codex, Behind the Harness — Dominik Kundel, OpenAI](https://www.youtube.com/watch?v=shRR1e2HXMk)

**한 줄 인사이트**
💡 Cerebras 기반의 초당 1,000토큰 추론 환경에서 네트워크 병목을 해결하기 위해 OpenAI는 웹소켓 상태 유지와 엄격한 샌드박스 보안을 결합한 오픈소스 Rust 기반 하네스를 구축했습니다.

**핵심 요약**
OpenAI의 Dominik Kundel이 초고속 AI 추론 시대에 모델의 성능을 극대화하고 안전하게 도구를 실행하기 위한 '하네스(Harness)' 구축 전략을 공유합니다. 그는 추론 속도가 빨라지면서 네트워크가 새로운 병목이 된 상황을 설명하고, 이를 해결하기 위한 상태 유지 웹소켓 도입과 컨텍스트 최적화 기법을 제시합니다. 나아가 안전한 파일 편집 및 셸 실행을 위한 OS별 샌드박스 환경과 자동 리뷰 서브에이전트를 통한 보안 관리 방안을 소개합니다.

1. **웹소켓 모드를 통한 네트워크 병목 해결**
   - Cerebras에서 GPT 5.3 Codex Spark가 초당 1,000개의 토큰을 처리하게 되면서 추론이 아닌 네트워크가 새로운 병목이 되었습니다.
   - 이를 해결하기 위해 HTTP 기반의 SSE 대신 상태 유지 웹소켓 모드를 도입하여, 매번 전체 컨텍스트를 재전송하는 대신 도구 호출 결과만 전송하도록 개선했습니다.

2. **컨텍스트 창 크기 및 효율성 최적화**
   - 도구를 '지연(deferred)' 상태로 표시하여 평소에는 컨텍스트 창에 넣지 않고, 모델이 실제로 필요로 할 때 도구 검색을 통해 호출하도록 설계했습니다.
   - 사용 가능한 기술 목록은 전체 컨텍스트 창의 2%로 제한하며, 컨텍스트가 커질수록 기술에 대한 설명을 자동으로 축소하여 효율성을 극대화합니다.

3. **OS별 맞춤형 샌드박스 및 보안 에이전트 도입**
   - 파일 편집은 전용 패치 적용 도구를 사용하고, 셸 실행은 macOS의 seatbelt, Linux의 bubblewrap, Windows의 자체 오픈소스 샌드박스를 통해 안전하게 격리합니다.
   - 권한 에스컬레이션 발생 시 읽기 전용 권한을 가진 자동 리뷰 서브에이전트가 작동하여, 사용자의 명시적 승인 여부와 대화 기록을 바탕으로 실행을 판단합니다.

4. **장기 목표 관리 및 오픈소스 Rust 하네스**
   - 장기 목표는 모델이 목표 업데이트 도구를 호출할 때까지 지속 프롬프트를 주입하는 방식으로 실행되며, 모호한 설명보다 구체적이고 검증 가능한 목표가 효과적입니다.
   - 이 하네스는 Apache 2 라이선스의 Rust 언어로 작성되었으며, 핵심 차별점은 Responses API에 있으므로 누구나 자유롭게 차용할 수 있습니다.
