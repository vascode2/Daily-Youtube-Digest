   - 컴퓨터 비전 파이프라인 구축과 같은 복잡한 CAD 도면 작업 예시에서 이러한 자가 검증 능력이 어떻게 실무에 적용되는지 잘 보여줍니다.
3. **토큰 효율성 극대화 및 강력한 스펙**
   - 법률 업무 처리 시 기존 대비 토큰 사용량을 7분의 1로 줄이고 전체 비용을 26% 절감하는 등 뛰어난 토큰 효율성을 자랑합니다.

4. **강화된 안전 장치 및 업계의 즉각적인 반응**

## [Building Closed-Loop Evals for a Multimodal Agent at Scale — Soumya Gupta & Jai Chopra, Uber](https://www.youtube.com/watch?v=31GUkCBD-Uc)

**한 줄 인사이트**
💡 Uber는 음식 사진을 개선하는 멀티모달 에이전트의 신뢰성을 확보하기 위해 오프라인과 온라인 신호를 결합한 폐쇄 루프(Closed-Loop) 평가 시스템을 구축했습니다.

**핵심 요약**
Uber의 머신러닝 엔지니어 Soumya Gupta와 제품 관리자 Jai Chopra는 중소 가맹점의 음식 사진을 보정하는 멀티모달 에이전트의 평가 프레임워크 설계 과정을 공유합니다. 이들은 원본 음식의 정체성을 유지하면서 플랫폼의 다양성을 해치지 않기 위해 겪었던 보상 해킹(Reward Hacking) 등의 한계를 설명합니다. 나아가 오프라인 피드백과 온라인 성능 지표를 유기적으로 연결하여 대규모 환경에서 안전하게 에이전트를 운영하는 최적의 평가 전략을 제시합니다.

1. **음식 사진 개선 에이전트의 고유한 도전 과제**
   - Uber Eats의 소규모 독립 가맹점을 돕는 이 에이전트는 원본 음식의 정체성과 브랜드 패키징을 정확히 유지하면서 사진 품질을 높여야 하는 복잡한 과제를 안고 있습니다.
   - 좁은 도메인에 특화된 멀티모달 평가를 위한 기존 표준이 부재한 상황에서, 시장의 다양성을 해치지 않고 품질을 일관되게 유지하는 것이 핵심입니다.

2. **보상 해킹 극복을 위한 가드레일 구축**
   - 에이전트가 평가 지표만 높이기 위해 비현실적인 이미지를 생성하는 보상 해킹(Reward Hacking) 문제를 방지하기 위해 엄격한 안전 가드레일을 설계했습니다.
   - 모델의 창의성과 엄격한 안전 기준 사이의 균형을 맞춤으로써, 왜곡되지 않고 신뢰할 수 있는 이미지만을 최종 사용자에게 노출합니다.

3. **오프라인과 온라인 피드백의 폐쇄 루프 통합**
   - Uber의 Applied AI 팀은 오프라인 평가 신호와 실제 서비스에서 발생하는 온라인 사용자 반응을 유기적으로 결합한 폐쇄 루프(Closed-Loop) 시스템을 구현했습니다.
   - 이를 통해 실험실 단계의 평가 지표와 실제 비즈니스 성과 간의 격차를 실시간으로 모니터링하고 모델을 지속적으로 최적화합니다.

4. **대규모 멀티모달 시스템의 운영 전략**
   - Soumya Gupta와 Jai Chopra는 대규모 프로덕션 환경에서 멀티모달 파이프라인을 안정적으로 운영하기 위한 실무적인 평가 설계 프레임워크를 제안합니다.
   - AI 엔지니어와 제품 관리자가 협력하여 좁은 도메인의 한계를 극복하고 에이전트의 성능을 정량적으로 측정하는 구체적인 방법론을 공유합니다.

## [평가(Evals)와 프롬프트가 AI 에이전트의 행동을 형성하는 방식 (AI Engineer)](https://www.youtube.com/watch?v=xyL2Ltkh-SA)

**한 줄 인사이트**

Google의 크리스 소자, 프리티카 바테자, 다니엘 뱀프 팀은 광고 크리에이티브를 정리하는 시드 에셋 에이전트를 구축하며 얻은 실전 교훈을 공유합니다. 이들은 단순한 프롬프팅의 한계를 극복하기 위해 평가(evals)를 단순 점수표가 아닌 실시간 피드백 신호로 활용하고, 트레이스 로그를 통해 실패 원인을 추적하는 방법을 설명합니다.

   - 실제 시스템에서는 프롬프트, 평가, 반복, 피드백이 결합된 루프 전체가 에이전트의 최종 행동을 결정합니다.

2. **단순 점수표를 넘어선 평가(Evals)의 역할**
   - 구글 팀은 평가를 최종 결과물을 매기는 성적표가 아니라 에이전트가 올바른 방향으로 학습하도록 돕는 핵심 피드백 신호로 재정의했습니다.

3. **트레이스 로그를 통한 실패 원인 분석**
   - 에이전트 실행 과정의 트레이스 로그를 면밀히 분석함으로써 예상치 못한 오작동과 실패가 발생한 근본 원인을 정확히 파악할 수 있습니다.

💡 프로덕션 트레이스를 파일시스템에 저장해 Claude Code 같은 코딩 에이전트에 직접 제공함으로써, 사람이 새벽에 깨어나 원인을 분석하는 대신 이미 수정 PR이 준비된 상태를 맞이할 수 있습니다.

**핵심 요약**
Arize의 Jason Lopatecki는 새벽에 긴급호출을 받고 원인을 분석하는 기존 방식에서 벗어나, 에이전트가 미리 문제를 조사하고 수정 PR까지 올려주는 자가 치유 시스템의 구조를 설명합니다. 대시보드 대신 파일 기반 트레이스를 활용하는 핵심 전환과 보안을 위한 VPC 구동 방식을 짚어보며, 개발자의 역할이 장애 대응자에서 리뷰어로 이동함을 보여줍니다.

1. **에이전트를 위한 관측 가능성(Observability)의 변화**
   - 관측 가능성은 더 이상 사람이 클릭해서 보는 대시보드가 아니라, 에이전트가 읽어내는 연기(telemetry)의 역할로 진화하고 있습니다.
   - 우버나 부킹 같은 기업들이 외부 모델에 프로덕션 시스템을 노출하지 않으므로, Arize는 하이브리드 VPC 환경에서 안전하게 샌드박스와 에이전트를 실행합니다.

2. **파일시스템 기반 트레이스라는 핵심 돌파구**
   - Claude Code 같은 코딩 에이전트는 파일 처리에는 능숙하지만 대시보드 활용에는 한계가 있어, 프로덕션 트레이스와 로그를 코드 바로 옆 파일로 다운로드합니다.
   - 에이전트는 수백만 개의 분기 중에서 추측하는 대신 소프트웨어가 실제로 거친 정확한 코드 경로를 파악하여 현실적인 수정안을 도출합니다.

3. **자가 치유 시스템의 한계와 개발자 역할의 전환**
   - 한 줄짜리 버그 수정은 에이전트에게 쉬운 사례이지만, 복잡하고 큰 규모의 수정은 여전히 인간의 개입과 드라이브가 필요합니다.
   - 이로 인해 개발자의 핵심 업무는 밤샘 장애 대응(responder)에서 에이전트가 올린 수정안을 검토하는 리뷰어(reviewer)로 이동합니다.
