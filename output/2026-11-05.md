4. **하루 30분, 2주 연습 시트 만들기**

## [AI 경쟁에 늦었다고? 다시 애플의 시간 | Siri AI가 앱 생태계를 어떻게 바꿀까, 왜 ...](https://www.youtube.com/watch?v=Iaxha5t8Vtg)

   - 11월 3일 공개된 Siri 개발자 프리뷰는 개발자가 앱 정보와 기능을 더 자유롭게 연결할 수 있도록 범위를 넓혔다.

2. **App Intents와 실행 구조**
   - 앱과 Siri를 잇는 App Intents의 역할, 그리고 실행을 조율하는 구조를 살펴본다.
   - 말을 이해하는 것만으로는 작업을 완료할 수 없다는 점이 논의의 핵심이다.

3. **삼성·구글과의 비교 및 한국어 Siri**
   - 삼성과 구글이 이미 구축한 멀티 앱 경험과 비교해 애플이 기회를 잡기 위한 조건을 짚는다.
   - 한국어 Siri AI 베타와 새 개발자 프리뷰를 구분하고, 앱 연동이 확대되기까지 남은 단계를 정리한다.

4. **메모리·칩·운영체제 협업과 반도체 영향**
   - 애플은 더 큰 모델을 아이폰 안에서 돌리기 위해 메모리 설계, 칩, 운영체제를 함께 조율하는 접근을 취한다.

## [Stop Giving Your AI Agents API Keys - Kim Maida, Keycard & Mason Egger, Temporal](https://www.youtube.com/watch?v=YqJ4asgj1R8)

**한 줄 인사이트**
💡 공유 API 키 대신 호출마다 발급되는 단기 OAuth 토큰과 Temporal의 durable execution을 결합하면, 에이전트를 안전하면서도 중단에 강하게 만들 수 있습니다.

**핵심 요약**
Keycard의 Kim Maida와 Temporal의 Mason Egger가 AI 에이전트의 보안과 신뢰성을 두 단계로 나눠 설명합니다. Kim은 공유 API 키를 OAuth 토큰 교환으로 대체하는 과정을 경비 승인 에이전트에 직접 구현하며 보여 줍니다. 이어 Mason은 Temporal로 실행 중인 에이전트를 강제로 종료한 뒤 중단된 지점에서 다시 이어 가게 합니다.

1. **공유 API 키 방식의 문제**
   - 모든 사용자와 에이전트가 같은 API 키를 쓰면 누가 어떤 작업을 했는지 추적할 수 없습니다. 워크숍의 "Before" 단계에서 이 상태를 먼저 재현합니다.
   - 에이전트에 키를 맡기는 방식은 권한 범위가 과도해지기 쉽다는 점이 출발점입니다.

2. **토큰 교환과 호출 단위 토큰**
   - 도구를 호출할 때마다 해당 호출에만 유효한 단기 토큰을 발급합니다. 이 토큰은 에이전트의 신원과 에이전트가 대행하는 사용자 정보를 함께 담습니다.
   - 프롬프트가 에이전트 루프를 지나며 각 도구 호출에 별도 토큰이 붙는 흐름을 단계별로 따라갑니다.

3. **경비 데스크 에이전트 구현**
   - 에이전트에 고유한 신원을 부여하고 코드에 토큰 교환을 연결해, 에이전트가 자기 자신으로서 동작하게 만듭니다.
   - 감사 로그에서 누가 경비를 제출하고 승인했는지 확인할 수 있습니다. 사용자는 가장(impersonation) 없이 추가하며, 승인 한도와 위임 체인도 추적합니다.

4. **Temporal의 durable execution**
   - 워커를 실행 도중 종료해도 에이전트는 중단된 지점부터 복구됩니다. 이미 끝난 LLM 호출을 다시 실행하지 않습니다.
   - 시크릿은 이벤트 히스토리에 저장하지 않도록 관리해, 내구성과 보안을 함께 확보합니다.

## [How Netflix Evaluates AI When There's No Right Answer - Cameron Wolfe, Netflix](https://www.youtube.com/watch?v=zLc8zeGeNaY)

**한 줄 인사이트**
💡 정답이 없는 창작형 과제의 평가는 보정된 사람 평가를 기준점으로 삼고, 이를 LLM 심사자와 A/B 테스트로 확장·검증하는 3단 구조로 풀어야 합니다.

**핵심 요약**
Netflix의 staff research scientist이자 Deep (Learning) Focus 뉴스레터 저자인 Cameron Wolfe는 창작 글쓰기처럼 정답이 하나가 아닌 과제를 어떻게 평가할지 설명합니다. 먼저 평가가 왜 어려운지, 특히 노이즈 문제를 짚고, 사람 평가, 오프라인 평가, 프로덕션 검증으로 이어지는 3단계 프레임워크를 제시합니다. 마지막으로 통계 기법과 Netflix 실제 사례로 이 틀이 현장에서 어떻게 작동하는지 보여줍니다.

1. **평가가 어려운 이유는 노이즈**
   - 정답을 검증할 수 있는 정도는 과제마다 스펙트럼처럼 다르며, 창작 글쓰기는 검증이 가장 어려운 쪽에 속합니다.
   - 이런 과제에서는 평가 결과에 노이즈가 많이 끼어 신뢰하기 어렵다는 점이 출발점입니다.

2. **사람 평가를 북극성으로 삼는 3단 프레임워크**
   - 프레임워크는 사람 평가, LLM 심사자와 루브릭 기반 오프라인 평가, A/B 테스트와 프로덕션 모니터링으로 구성됩니다.
   - 사람 평가는 가이드라인으로 평가자를 보정(calibration)해야 하며, 필요한 데이터의 양과 종류도 함께 설계해야 합니다.

3. **LLM 심사자와 루브릭으로 오프라인 평가 확장**
   - LLM 심사자와 루브릭을 사용해 평가를 대규모로 확장하되, 사람이 만든 "golden" 데이터와 대조해 심사자를 검증합니다.
   - 이렇게 하면 사람 평가의 신뢰성을 유지하면서 반복 속도를 높일 수 있습니다.

4. **통계로 노이즈를 제어하고 실제 환경에서 확인**
   - 검정력 분석(power analysis), 오차 막대(error bars), 리샘플링으로 노이즈에 대응합니다.
   - 프로덕션 모니터링과 A/B 테스트로 실제 결과를 확인하며, Netflix 프로젝트에서는 LLM 심사자 점수가 시청자의 시청 중단과 인과적으로 연결된 것으로 나타났습니다.

## [Why Waiting for the Next AI Model Can Pay Off - John Stecher, Blackstone & Scott Worland, Norm AI](https://www.youtube.com/watch?v=ra8X7_bnujw)

**한 줄 인사이트**
💡 모델이 계속 좋아지는 시대에는 정교하게 만든 워크플로 코드가 오히려 걸림돌이 될 수 있어서, 탄탄한 데이터와 평가 체계에 투자하고 앱은 버리고 다시 만들 수 있다고 전제하는 편이 유리하다.

**핵심 요약**
Blackstone CTO John Stecher와 Norm AI CTO Scott Worland가 모델이 발전해도 무너지지 않는 기술을 어떻게 만들지 각자의 경험으로 이야기한다. John은 에이전트보다 데이터 전략과 자동화된 처리 흐름이 먼저라고 강조하고, 투자 대비 효과(ROI)에 따라 다음 모델을 기다릴지 판단한다고 설명한다. Scott은 직접 라벨링한 대규모 평가 세트로 기존 워크플로 코드가 성능을 막고 있음을 확인하고 플랫폼을 재구축한 과정을 들려준다.

1. **에이전트보다 데이터와 직통 처리가 먼저**
   - John은 AI 에이전트를 제대로 쓰려면 탄탄한 데이터 전략이 선행되어야 한다고 말한다.
   - 사람 개입 없이 처음부터 끝까지 처리하는 straight-through processing도 에이전트 시대에 여전히 중요하다고 본다.

2. **워크플로 코드가 오히려 방해가 된 경험**
   - Norm AI는 초기에 정교한 워크플로 중심으로 시스템을 구축했지만, 에이전트가 등장하면서 그 코드의 상당 부분이 쓸모없어졌다.
   - 금융 서비스 분야에서 직접 라벨링한 대규모 평가 세트가 이를 객관적으로 보여 주었고, 팀은 플랫폼을 다시 만들었다.

3. **ROI와 기다림의 판단**
   - John은 지금 투자할 때의 ROI와 더 나은 모델을 기다렸을 때의 이득을 비교해 결정한다고 설명한다.
   - Scott은 "bitter lesson"의 관점에서 프런티어가 움직이는 만큼 어디에 깊게, 어디에 가볍게 투자할지 구분한다고 말한다.

4. **빠른 PoC, 어려운 프로덕션, 다시 만들기**
   - 개념 증명은 빠르게 만들 수 있지만 진짜 어려운 부분은 프로덕션 단계이며, 일부 영역은 여전히 사람의 검토가 필요하다.
   - 내부 앱은 유지보수하기보다 버리고 다시 만들 수 있는 대상이 되었다고 John은 본다.
