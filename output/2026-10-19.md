## [How to Know When an AI Agent Can Work Unsupervised — Evan Kormos, Coinbase](https://www.youtube.com/watch?v=_4Ph2dhmUFI)

**한 줄 인사이트**
💡 에이전트를 믿을 수 있는지는 모델의 성능이 아니라 루프 안의 검증(check)과 eval의 품질이 결정하며, 신뢰는 완전 감독에서 샘플링, 예외 처리 순으로 단계적으로 쌓아야 합니다.

**핵심 요약**
엔터프라이즈 금융 서비스 경력 15년의 Coinbase 플레이어-코치 Evan Kormos가, 정책 중심의 규제 업무에 에이전트를 도입하는 실용적인 방법을 설명합니다. 그는 업무를 DAG와 루프로 모델링해 에이전트가 맡을 단계를 가려내고, eval과 trace를 새로운 신뢰 수단으로 삼아 감독 수준을 점차 낮추는 흐름으로 논지를 전개합니다.

1. **정책은 원조 시스템 프롬프트다**
   - 규제 산업의 정책 문서는 사람이 따르도록 쓴 지침이라는 점에서 에이전트에게 주는 시스템 프롬프트와 같은 역할을 한다고 봅니다.
   - 에이전트가 들어갈 자리는 사람, 프로세스, 기술이라는 세 축 안에서 판단합니다.

2. **워크플로는 DAG, 노드 안은 루프**
   - 업무 흐름을 DAG(방향성 비순환 그래프)로 그리고, 각 노드 내부는 실행과 점검을 반복하는 루프로 모델링합니다.
   - 예외 흐름과 병목을 함께 드러내야 에이전트를 어디에 둘지 보입니다.

3. **루프는 검증만큼만 믿을 수 있다**
   - 입력 품질이 좋아야 출력 품질도 좋으며, 루프의 신뢰도는 그 안의 check 수준을 넘을 수 없다고 강조합니다.
   - eval과 trace는 에이전트의 동작을 확인하게 해 주는 새로운 신뢰 장치 역할을 합니다.

4. **에이전트가 맡을 단계 선택과 감독 단계 전환**
   - 어떤 단계를 에이전트가 소유할지 정한 뒤, 완전 감독 → 샘플링 검토 → 사람은 예외만 처리하는 3단계로 자율성을 넓힙니다.
   - 각 단계로 넘어가는 근거는 eval과 trace로 쌓은 신뢰입니다.

2. **시나리오별 모델 차이 확인**

   - 프롬프트 엔지니어링으로 일부 격차는 줄일 수 있지만, 이미지 이해 격차는 해결되지 않는다고 설명합니다.

## [My Jev Pi Durable Agent CURATES News: HYPE, FACT, or SIGNAL](https://www.youtube.com/watch?v=OLqP8jxJ0Wc)

**한 줄 인사이트**
💡 코드가 거의 공짜가 된 시대에는 취향·판단력·시스템 설계가 실력을 가르며, 에이전트를 얼마나 많이 '루프 밖'에서 돌리느냐가 곧 에이전틱 엔지니어링의 척도라는 주장입니다.

**핵심 요약**
IndyDevDan은 프롬프트를 주고받으며 에이전트를 지켜보는 방식(in the loop)에서 벗어나, 사람이 일하지 않아도 에이전트가 먼저 일하는 'out loop'로 넘어가야 한다고 주장합니다. 이를 증명하기 위해 Pi Durable 위에 만든 Durable News Agent가 매분 뉴스를 수집·선별하는 과정을 시연하고, 그 아키텍처와 비용 구조를 설명합니다.

1. **프로액티브 에이전트와 In·Near·Out Loop**
   - 프로액티브 에이전트는 '내구성 있는 에이전트(durable agent) + 샌드박스 안의 트리거'로 정의됩니다. 사람이 시키기 전에 먼저 일하고 결과만 기다립니다.
   - 하루 종일 나 대신 돌아가는 자율 작업 스레드가 몇 개인지가 에이전틱 엔지니어링 실력의 척도라고 말합니다.

2. **Hype · Facts · Signal 분류**
   - Hype는 근거 없는 흥분, Facts는 객관적으로 참이지만 당장 쓸 수 없는 정보(대규모 수학 증명 공개 등)입니다.
   - Signal은 지금 바로 행동할 수 있는 고레버리지 정보(새로운 SOTA 모델 출시 등)로, 모든 뉴스 항목을 이 세 구간으로 점수화합니다.

3. **저렴한 jev 분류기로 만든 파이프라인**
   - LLM 앞단에 0.5초 미만의 값싼 jev 분류기를 두어 수집·게이트·중복 제거·랭킹 단계마다 걸러냅니다. 덕분에 토큰 비용을 낮춰 cron 에이전트가 매분 돌 수 있습니다.
   - 관련 없는 기사는 차단하고 중복 보도를 제거하며 여러 출처에서 주장을 교차 검증합니다.

4. **계층형·분리형 클라이언트 아키텍처**
   - SQLite 기반 서버 API 뒤에 Pi Durable, 커스텀 pi 에이전트 하네스, 통합 SDK를 층층이 쌓았습니다. 웹 생성형 UI, 터미널 TUI, CLI, cron 트리거가 모두 실시간 동기화되는 얇은 클라이언트입니다.
   - 로컬 M4 Mac mini 박스와 클라우드 exe.dev 샌드박스 양쪽에서 동작합니다.

5. **데이터 플라이휠과 취향 튜닝**
   - 뉴스 카드에 추천/비추천을 누르고, 키워드·출처 가중치를 일반 채팅으로 조정하면 에이전트가 다음에 보여줄 내용이 계속 정교해집니다.
   - 코드는 복제하기 쉬우니, 자신의 취향 프로필을 붙여 직접 시스템을 만들라고 권합니다.
