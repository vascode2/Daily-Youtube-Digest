## [AutoKliq 공개: 메타 개발자 두 명이 만든 AI 썸네일 서비스](https://www.youtube.com/watch?v=YiKAbr0KSPk)

**한 줄 인사이트**
💡 썸네일에는 정답이 없기 때문에 직접 만든 AutoKliq는 분석, 스킬, 브랜드 가이드로 피드백을 쌓아 가고, 앞으로의 핵심은 에이전트가 쓰기 쉽게 만드는 것이라고 주장합니다.

**핵심 요약**
유튜브 채널 운영자 알렉스가 썸네일 제작에 계속 어려움을 겪었고, 써 본 서비스마다 아쉬움이 남아 메타 개발자 두 명과 함께 직접 AutoKliq를 만들었습니다. 10월 10일 라이브에서 먼저 자세히 소개했던 이 서비스의 기능을 차례로 보여 주고, 웹사이트를 클릭하는 대신 에이전트에 일을 맡기는 방식으로 넘어갑니다. 마지막에는 에이전트가 효과적으로 쓰기 쉽게 만드는 것이 앞으로의 핵심이라는 결론으로 이어집니다.

1. **정답 없는 썸네일 문제와 게임 같은 설계**
   - 썸네일은 하나의 정답이 없어 채널 운영 중 가장 힘들었던 부분이며, 기존 서비스들도 만족스럽지 않아 직접 만들게 되었습니다.
   - 크리에이티브 디렉터는 게임처럼 레벨이 오르고 크레딧 체계도 게임 방식으로 설계했습니다.

2. **채널 분석과 썸네일 스킬**
   - 분석 기능은 내 채널과 비슷한 채널을 벤치마킹해 에이전트가 채널 전략을 파악하도록 돕습니다.
   - 스킬은 인터넷에 흩어진 썸네일 전략을 모아 만들었으며, 하네스 엔지니어링 관점에서 다룹니다.

3. **브랜드 가이드와 한 번에 6장 생성**
   - 브랜드 가이드에는 지켜야 할 것과 피해야 할 것이 정리되고 피드백이 계속 누적됩니다.
   - 썸네일은 한 번의 생성으로 이미지 6장을 만들어 선택지를 넓혀 줍니다.

4. **웹사이트 대신 에이전트와 MCP**
   - 사람이 사이트를 직접 클릭하지 않고, 단일 프롬프트와 MCP로 에이전트에 작업을 위임하는 방식을 설명합니다.
   - 핵심은 에이전트가 효과적으로 쓰기 쉽게 만드는 것이며, 프로듀서 에이전트 라이브 데모로 보여 줍니다.

## [Claude Code 팀 엔지니어들은 업무의 70~80%를 Slack에서 처리한다](https://www.youtube.com/watch?v=VAOdUAkVGpE)

**한 줄 인사이트**
💡 Claude Code 팀은 세션 안에서 직접 코딩하기보다 Slack에 목표를 던지고, 세션 밖에서 루프를 돌리고, 근거를 보고받는 방식으로 일한다.

**핵심 요약**
커리어해커 알렉스가 Claude 공식 채널의 "How the Claude Code team uses Claude Code" 영상을 해설합니다. 원본 클립 인용, 모션 재현, 자신의 Mac Mini 환경 재현, 이번 주에 해볼 방법 한 가지 순서로 6가지 워크플로를 보여줍니다. 원본 영상의 최상위 댓글(503 좋아요)이 "말로만 하지 말고 보여 달라"였기 때문에 말보다 화면 중심으로 구성했습니다.

1. **Slack에서 목표를 맡기기**
   - Claude Code 팀은 업무의 상당 부분을 Slack에서 처리하며, 목표를 먼저 전달하는 방식으로 일합니다. 관련 공식 문서로 Claude Tag(Team·Enterprise 플랜)가 소개됩니다.

3. **리뷰는 큰 그림을 보는 일**
   - 코드 한 줄씩 확인하기보다 전체 방향과 구조를 점검하는 것이 리뷰의 핵심이라는 관점입니다. 공식 문서 Code Review와 함께 소개됩니다.

4. **Fan-out 후 반박**
   - 여러 에이전트에 작업을 나눠 돌린 뒤 결과에 반박을 거치게 하는 흐름입니다. Dynamic workflows 문서가 관련 자료로 제시됩니다.

5. **근거로 보고받기와 집착하지 않기**
   - 보고는 실제 로그와 명령 결과 같은 증거 형태로 받는다는 방식입니다. 마지막 챕터 "Don't Obsess"는 모든 과정에 지나치게 매달리지 말자는 취지이며, 영상 말미에 요약과 체크리스트가 정리됩니다.

**한 줄 인사이트**
💡 에이전트가 90분 동안 200번 호출해 사용자를 Resy에서 퇴출시킨 사건은, 에이전트에게 부족한 것이 의도가 아니라 한도와 권한 구조임을 보여 줍니다.

**핵심 요약**
Keycard의 Allie Howe가 진행하는 키노트 패널로, Keycard CEO Ian Livingstone, JPMorgan Chase의 Michael Davis, OAuth 공동 창시자이자 AAuth 제작자인 Dick Hardt가 참여합니다. 이들은 기업이 왜 에이전트에게 실질적인 자율성을 주지 못하는지 짚고, 기존 인증·권한 체계의 한계에서 출발해 새로운 통제 방식을 논의합니다. 마지막에는 상업, 프로토콜, 감사 로그, 그리고 P(doom)까지 이야기를 확장합니다.

1. **OAuth와 기존 권한 모델의 한계**
   - OAuth 스코프는 에이전트에게 너무 거칠다는 점이 논의됩니다. 에이전트의 행동 범위를 세밀하게 제한하기 어렵기 때문입니다.
   - 은행이 거래를 승인해 온 방식에서 에이전트 권한 부여의 힌트를 찾는 대목도 있습니다.

2. **에이전트를 신입 개발자처럼 온보딩하고 미션을 부여하기**
   - 에이전트를 신입 개발자처럼 온보딩하고, 단순한 권한 목록 대신 "미션"을 주는 접근이 제시됩니다.
   - 단순한 호출 횟수 제한(rate limit) 대신 예산(budget) 개념으로 통제하자는 아이디어도 나옵니다.

3. **에이전트 상거래와 열린 웹**
   - 웹은 에이전트를 위해 설계되지 않았기에 "know your agent" 같은 개념이 필요하다는 논의가 이어집니다.
   - 열린 프로토콜과 폐쇄형 생태계(walled garden) 중 무엇이 바람직한지도 다룹니다.

4. **두뇌와 손의 분리, 그리고 감사 로그**
   - Resy 사례처럼 선의로 움직여도 한도가 없으면 사고가 나므로, 에이전트의 판단(두뇌)과 실행(손)을 분리하는 설계가 논의됩니다.
   - 감사 로그는 에이전트 바깥에 두어야 한다는 점과 로보틱스의 교훈, 안전한 소프트웨어 팩토리 등 실무 사례도 언급됩니다.

5. **모델 업그레이드와 CI 게이트**

1. **시작하기: ChatGPT 이해, 가입, 요금제**
   - ChatGPT가 검색창과 어떻게 다른지 설명하고, 로그인 없이 질문하는 방법과 가입 절차를 안내합니다.

2. **화면 구성과 첫 대화**
   - 화면의 각 영역을 하나씩 살펴보고, 첫 질문을 던진 뒤 답변 아래 버튼과 메시지 수정 방법을 익힙니다.

3. **좋은 질문 공식 4가지**
   - 냉장고 사진 예시로 같은 질문을 4단계로 구체화해 답변이 어떻게 달라지는지 비교합니다.
   - 이어서 모델(추론 수준)을 고르는 기준을 설명합니다.

4. **부가 기능과 관리·설정**

   - 설정에서는 메모리, 말투, 학습 끄기, 보안과 함께 사용량 및 한도를 확인합니다.

5. **활용·후기·단점**
   - 실전 활용 3가지와 루리웹, 더쿠, 브런치, Reddit 등에서 모은 사용자 후기, 팁 7가지를 소개합니다.
