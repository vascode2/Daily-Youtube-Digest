## [메타 시니어 엔지니어가 잘때도 에이전트를 돌리는 법 | 에이전트 시대의 터미널 Herdr](https://www.youtube.com/watch?v=U9AConAimzM)

**한 줄 인사이트**
💡 AI 에이전트가 백그라운드에서 장시간 작업을 수행하는 시대에는 에이전트의 상태를 실시간으로 감지하고 제어할 수 있는 에이전트 친화적 터미널 멀티플렉서가 필수적입니다.

**핵심 요약**
실리콘밸리 개발자이자 메타 시니어 엔지니어 출신인 발표자가 여러 AI 에이전트를 동시에 구동할 때 발생하는 병목 현상과 비효율성을 지적하며 새로운 오픈소스 도구를 소개합니다. 기존 tmux의 세션 유지 기능에 에이전트 상태 인식 및 자동화 스킬을 더한 'herdr'의 핵심 개념과 주요 기능을 데모와 함께 설명합니다. 마지막으로 실제 프로덕트인 AutoKliq 개발 과정에 Claude Code 에이전트 3개를 동시에 붙여 풀 리퀘스트(PR)까지 완료하는 실전 워크플로우를 보여주며 에이전트 중심 개발 환경의 미래를 제시합니다.

1. **에이전트 시대에 터미널 멀티플렉서가 다시 주목받는 이유**
   - AI 에이전트가 사용자가 화면을 보지 않는 동안에도 수십 분간 백그라운드에서 스스로 작업을 수행하게 되면서, 터미널을 닫아도 프로세스를 살려두는 tmux 같은 멀티플렉서의 필요성이 커졌습니다.
   - 하지만 기존 tmux는 화면 내부에서 에이전트가 승인을 기다리는지(blocked), 작업을 완료했는지 알 수 없어 사용자가 일일이 모든 탭을 확인해야 하는 병목이 발생합니다.

2. **에이전트의 상태를 이해하는 터미널 멀티플렉서, herdr**
   - herdr는 tmux의 서버-클라이언트 구조와 세션 유지 기능을 그대로 유지하면서, 에이전트가 승인 대기(blocked), 작업 중(working), 완료(done) 등 어떤 상태에 있는지 감지하여 사이드바와 알림으로 알려줍니다.
   - 2024년 8월 Y Combinator에 합류한 Apache-2.0 라이선스의 오픈소스이며, 터미널 앱을 완전히 종료하거나 서버를 재시작해도 `claude --resume` 등을 통해 대화 세션을 완벽히 복원합니다.

3. **Claude Code 3개를 동시 구동하는 실전 개발 데모**
   - 개발 중인 AutoKliq 프로젝트에서 오케스트레이터 역할을 하는 Claude Code 하나에 명령을 내리면, herdr 스킬을 통해 자동으로 git worktree를 만들고 pane을 쪼개어 하위 에이전트 3개를 기동합니다.
   - 사용자는 각 에이전트의 진행 상황을 `herdr agent read` 명령어로 화면 전환 없이 확인하고, 승인이 필요한 에이전트의 알림이 올 때만 개입하여 작업을 효율적으로 병렬 처리합니다.

4. **에이전트 퍼스트(Agent-first) 개발 도구의 미래**
   - 에이전트가 단순한 도구를 넘어 스스로 개발 환경을 조작하는 런타임으로 진화함에 따라 터미널(herdr), IDE(Orca), 브라우저(Aside) 등 전용 도구들의 생태계가 빠르게 구축되고 있습니다.
   - 발표자는 여러 에이전트를 동시에 제어하며 최종 코드를 취합하고, Codex 리뷰어까지 붙여 하루 만에 PR을 제출하는 워크플로우를 통해 생산성의 극적인 향상을 증명합니다.

## [더 늘어난 HBM4 용량과 NVIDIA Rubin CPX 부활 루머 | 삼성의 13Gbps HBM4가 중요한 이유](https://www.youtube.com/watch?v=-llJ8649mkU)

**한 줄 인사이트**
💡 삼성의 13Gbps HBM4는 단순한 속도 경쟁을 넘어, NVIDIA Rubin CPX의 대역폭 한계를 극복하고 HBM 공급 부족 상황에서 GPU 생산 효율을 극대화하는 핵심 열쇠가 될 수 있습니다.

**핵심 요약**
최근 공급망 정보를 통해 한동안 라인업에서 사라진 것으로 여겨졌던 NVIDIA의 Rubin CPX 부활 가능성이 제기되고 있습니다. 이 칩은 기존 GDDR7 대신 168GB HBM4를 탑재하여 표준 Rubin에 준하는 연산 성능을 낼 것으로 기대됩니다. 본 분석에서는 삼성전자가 강조하는 13Gbps HBM4의 마진이 시스템 설계 관점에서 갖는 의미와 향후 AI 에이전트 시대의 GPU 수요 변화를 전망합니다.

1. **NVIDIA Rubin CPX의 부활 루머와 스펙 변화**
   - 기존의 128GB GDDR7 대신 168GB HBM4를 탑재할 것이라는 공급망 정보가 흘러나오며, 연산 성능이 표준 Rubin에 한층 더 가까워질 것으로 예상됩니다.
   - 공개된 HBM4 구성을 역산하면 8단 24GB HBM4 모듈 7개를 혼합하는 독특한 결합 방식이 도출됩니다.

2. **삼성전자 13Gbps HBM4의 시스템 설계상 이점**
   - 삼성의 11.7Gbps 속도를 적용하면 약 21TB/s의 대역폭을 얻을 수 있지만, 12.3Gbps 이상을 확보하면 Rubin 표준형에 준하는 22TB/s 대역폭 달성이 가능해집니다.
   - 삼성전자가 강조하는 최대 13Gbps의 성능 마진은 단순 속도 경쟁이 아니라, HBM 공급 부족 상황에서 적층 수와 용량을 줄이면서도 고대역폭을 유지해 GPU 생산량을 늘리는 설계적 돌파구가 됩니다.

3. **AI 에이전트 및 롱 컨텍스트 시대의 GPU 역할 분담**
   - AI 에이전트와 롱 컨텍스트(Long Context)의 증가로 인해 입력 데이터를 미리 처리하는 Prefill 전용 GPU의 필요성이 다시 대두되고 있습니다.
   - 이에 따라 연산 성능과 대역폭의 균형을 맞춘 CPX와 표준 Rubin 간의 명확한 역할 분담이 이루어질 것으로 보입니다.

4. **향후 시장 수요 변화와 GTC 베를린 주목**
   - Rubin CPX가 기존 Rubin을 대체하는지 혹은 라인업에 추가되는지에 따라 전체 HBM 수요 예측이 완전히 달라질 수 있습니다.
   - 미확인 공급망 정보와 공식 발표를 명확히 구분해야 하며, 오는 10월 GTC 베를린에서 공개될 공식 로드맵이 핵심 검증 포인트가 될 것입니다.

## [I transferred the exact same movement to a different world](https://www.youtube.com/watch?v=MVZgQF0XwhQ)

**한 줄 인사이트**
💡 Higgsfield AI의 Genjutsu는 기존 비디오의 구조와 카메라 움직임을 완벽히 유지하면서 배경이나 캐릭터 스타일만 정교하게 변경할 수 있는 강력한 비디오 투 비디오(Video-to-Video) 도구입니다.

**핵심 요약**
제작자는 Higgsfield AI의 Genjutsu 플랫폼을 활용하여 기존 비디오의 프롬프트를 분석하고 새로운 스타일로 변환하는 과정을 상세히 소개합니다. Object Swap과 Motion Transfer 기능을 통해 비행기 창밖 풍경을 빙하 지대로 바꾸고, 파쿠르 영상의 역동적인 움직임을 3D 공간 및 2D 애니메이션으로 완벽하게 이식하는 과정을 보여줍니다. 이를 통해 무에서 유를 창조하는 대신 기존 소스를 활용해 정교한 AI 콘텐츠를 확장하는 실용적인 워크플로우를 제시합니다.

1. **Genjutsu의 핵심 기능인 Object Swap과 Motion Transfer**
   - Object Swap은 원본 비디오의 구도와 카메라 움직임을 유지하면서 특정 객체나 배경만 다른 이미지나 텍스트 프롬프트로 교체하는 기능입니다.
   - Motion Transfer는 원본 영상 속 인물의 복잡한 물리적 움직임을 그대로 추출하여 완전히 새로운 3D 공간이나 2D 그래픽 캐릭터에 이식합니다.

2. **Object Swap을 활용한 비행기 창밖 풍경 변환**
   - 5초 분량의 비행기 창밖 촬영 영상에서 수평선 아래의 바다와 마을을 3장의 참조 사진을 활용해 얼음 군도(ice archipelago)로 자연스럽게 변경했습니다.
   - 프롬프트 작성을 통해 변경할 요소 1가지와 보존해야 할 요소 11가지, 금지할 요소 11가지를 명확히 구분하여 왜곡 없는 결과물을 얻었습니다.

3. **Motion Transfer를 통한 파쿠르 움직임의 다차원 이식**
   - 8초짜리 파쿠르 영상의 역동적인 움직임을 추출하여, 한 번은 3D 하늘 항구(sky harbor) 배경으로, 또 한 번은 2D 흑백 카툰 스타일로 두 차례 이식하는 데 성공했습니다.
   - 인물에게 텍스트 문장을 부여하는 3D 버전과 특정 이미지를 부여하는 2D 버전의 차이를 비교하며 모션 보존 능력을 검증했습니다.

4. **비디오 투 비디오(Video-to-Video) AI의 실무적 가치**
   - 텍스트만으로 영상을 처음부터 생성하는 방식과 달리, 기존 비디오 소스를 기반으로 변형을 주기 때문에 콘텐츠 제작자의 작업 효율을 극대화합니다.
   - 원본 비디오와 생성된 3가지 결과물을 화면 분할(2분할, 3분할) 방식으로 직접 비교 검증하여 기술의 실용성과 정교함을 입증했습니다.

## [Why AI Agents Need Million-Token Context — Thomas Wolf & Olive Song, MiniMax](https://www.youtube.com/watch?v=5Cxe5dv2Xlw)

**한 줄 인사이트**
💡 MiniMax M3는 100만 토큰의 컨텍스트 창과 멀티모달 기능을 결합하여 복잡한 에이전트 환경에서 실질적인 성능 향상을 이끌어냅니다.

**핵심 요약**
Hugging Face의 공동 창업자인 Thomas Wolf와 MiniMax의 RL 리드인 Olive Song이 대담을 통해 MiniMax M3 모델의 혁신과 개발 비하인드를 공유합니다. 이들은 에이전트가 복잡한 환경에서 작동하기 위해 왜 대규모 컨텍스트 창이 필수적인지 설명하며, 인턴이 설계한 희소 주의집중(Sparse Attention) 아키텍처의 비하인드 스토리를 밝힙니다. 나아가 초기 단계부터 멀티모달로 설계된 M3 모델이 어떻게 자체 연구를 자동화하고 다음 버전인 M3.1 개발에 기여하고 있는지 그 흐름을 제시합니다.

1. **100만 토큰 컨텍스트의 필요성과 에이전트의 진화**
   - MiniMax M3는 단순한 텍스트 처리를 넘어 긴 대화 기록, 도구 응답, 복잡한 환경 정보를 동시에 유지하기 위해 실질적인 100만 토큰 컨텍스트 창을 지원합니다.
   - 에이전트가 프레젠테이션이나 긴 비디오와 같은 멀티모달 데이터를 깊이 있게 이해하고 작동하기 위해서는 대규모 컨텍스트가 필수적입니다.
2. **인턴이 설계한 희소 주의집중 아키텍처와 효율성 극대화**
   - MiniMax의 독창적인 희소 주의집중(Sparse Attention) 아키텍처는 놀랍게도 한 인턴의 설계에서 시작되어 100만 토큰의 효율적인 처리를 가능하게 했습니다.
   - MiniMax의 개방적인 연구 문화 덕분에 직급에 상관없이 혁신적인 아이디어가 실제 프론티어 모델 학습에 빠르게 반영될 수 있었습니다.
3. **초기 단계부터 통합된 멀티모달 학습과 3억 사용자 서비스**
   - M3 모델은 텍스트, 이미지, 비디오를 동일한 모델 내에서 완벽히 이해할 수 있도록 학습의 첫 단계부터 멀티모달로 설계되었습니다.
   - MiniMax는 이미 3억 명 이상의 사용자를 보유한 대규모 AI 제품들을 운영하고 있으며, 커뮤니티 피드백을 반영하기 위해 오픈소스 모델 공개 정책을 유지하고 있습니다.
4. **에이전트 하네스를 통한 AI 연구 자동화와 M3.1 개발**
   - MiniMax는 자체 연구 속도를 높이기 위해 내부적으로 에이전트 하네스(Agent Harness) 시스템을 구축하여 AI 연구 과정을 자동화하고 있습니다.
   - 현재 M3 모델은 단순히 완성된 제품에 머무는 것이 아니라, 스스로 다음 버전인 M3.1 모델을 학습시키고 개선하는 연구 도구로 활용되고 있습니다.

## [GPT-6 Astra: OpenAI가 걱정할 정도로 너무 뛰어난 성능](https://www.youtube.com/watch?v=Spuza-KwTJ4)

**한 줄 인사이트**
💡 OpenAI의 새로운 GPT-6 Astra는 뛰어난 비용 효율성과 벤치마크 압도 속에서도 AI 안전 연구자들에게 사고 과정 추적의 어려움이라는 새로운 과제를 안겨주었습니다.

**핵심 요약**
