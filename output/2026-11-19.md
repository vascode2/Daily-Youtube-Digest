## [Filming a Movie with Claude Fable 5.2 and Blender Sets | How to Create Videos with Claude [9-Minu...](https://www.youtube.com/watch?v=D4B09If34_w)

**한 줄 인사이트**
💡 네 문단짜리 프롬프트 하나로 Claude Fable 5.2가 Blender 세트와 카메라 7대를 만들고 Seedance 2.5로 60초 무대사 단편을 완성했으며, 전체 비용은 약 1,253 크레딧이었다.

**핵심 요약**
Claudical 채널은 AI 영상에서 카메라가 지시를 따르지 않는 문제를 Blender 프리비즈로 풀어 보려 한다. Claude Fable 5.2에 프롬프트를 주고 Higgsfield MCP와 Blender를 연결해, 단편 '등대지기와 하늘 고래'를 만드는 전 과정을 순서대로 보여 준다. 가입과 MCP 연결부터 480p 초안, 어색한 장면 수정, 1080p 최종본, 트레일러까지 단계별로 진행하고 크레딧 비용도 공개한다.

1. **역할 분담과 준비 과정**
   - Fable 5.2가 연출과 제작 진행을 맡고, Higgsfield MCP를 통해 설계 도안, 3D 모델, 영상 생성을 호출한다. Higgsfield에 가입한 뒤 MCP를 Claude에 연결하는 과정부터 보여 준다.
   - 영상은 Blender에서 만든 흑백 프리비즈를 기준으로 Seedance 2.5가 생성한다. 이렇게 카메라 움직임을 통제하려는 접근이다.

2. **네 문단 프롬프트의 구성**
   - 프롬프트는 외딴 섬에서 매일 저녁 등불을 켜는 등대지기가 구름 속을 헤엄치는 거대한 고래를 만난다는 줄거리다. 컷 구성과 연출은 Claude에 맡긴다.
   - 제작 방식도 지정한다. Blender 세트와 카메라로 프리비즈를 만들고, 크레딧 추가 전에 비용을 먼저 알리며, 480p 초안부터 한 단계씩 진행하고, 영상 제작 전에 프리비즈를 보여 달라고 요청한다.

3. **세트, 프리비즈, 480p 초안**
   - Fable 5.2는 GPT Image 2.6으로 설계 도안 3장, Tripo H3.1로 3D 모델 3개를 만들었다. Blender에는 카메라 7대를 설치했고 총 1,440프레임(24fps, 60초)이다.
   - 480p 초안이 프리비즈를 얼마나 따르는지 확인했다. 인형처럼 어색하게 나온 계단 장면은 다시 만들었고, 두 컷을 더 고쳤다.

4. **최종본, 트레일러, 비용**
   - 1080p 최종본까지 만든 뒤, 프롬프트 하나로 15초 트레일러도 만들 수 있는지 시험한다. Blender 창을 보면서 작업하려면 Blender와 직접 연결해야 한다고 설명한다.
   - 크레딧은 프리비즈까지 29.25, 480p 초안 7컷 187.5, 계단 컷 재제작 25.5, 두 컷 추가 수정 45, 1080p 966이다. 영화 전체는 1,253.25이고 트레일러 45를 더하면 1,298.25다.

**한 줄 인사이트**

**핵심 요약**
Thariq Shihipar는 격투 게임을 바이브 코딩하다가 자기 캐릭터가 어떻게 동작하는지 알 수 없게 된 경험에서 출발합니다. CODE Summit 2026에서 그는 Bitter Lesson을 다시 해석하고, AI의 들쭉날쭉한 최전선(jagged frontier)과 매끄러운 내부(smooth interior)를 대비합니다. 이어 라이브 데모로 읽기 쉬운 명세와 커스텀 스크립트 언어를 활용해 사람 중심의 AI 개발 방식을 보여줍니다.

1. **Bitter Lesson을 다시 읽다**
   - Bash, React, MCP 같은 도구와 AI 아트를 사례로 Bitter Lesson이 개발 방식에 주는 의미를 재검토합니다.
   - AI 도입은 사람을 중심에 두는 방향이어야 한다고 강조합니다.

2. **산업혁명과 소프트웨어 르네상스**
   - 산업혁명에 빗대어, AI가 소프트웨어 제작 방식을 근본적으로 바꾸는 시대를 "소프트웨어 르네상스"로 규정합니다.
   - 이 변화가 단순한 자동화가 아니라 창작 기회의 확장이 되어야 한다는 관점을 제시합니다.

3. **들쭉날쭉한 최전선과 매끄러운 내부**
   - 모델 능력의 경계는 울퉁불퉁하지만, 경계 안쪽은 안정적으로 잘 작동하는 영역이라고 설명합니다.
   - 모델이 아는 지식을 시각화해 어디까지 믿고 맡길 수 있는지 가늠하는 방법을 소개합니다.

4. **바이브 코딩이 개발자를 소외시킬 때**
   - 격투 게임 사례에서, 에이전트에 모두 맡기면 개발자가 자기 코드의 동작을 이해하지 못하게 됩니다.
   - 해법으로 엔진 코드와 사람이 읽을 수 있는 명세를 분리하는 구조를 제안합니다.

5. **라이브 데모: 게임용 스크립트 언어**
   - 게임을 위한 커스텀 스크립트 언어를 만들어, 에이전트가 작업하더라도 창작자가 내용을 읽고 수정할 수 있게 합니다.
   - IDE 워크플로우와 결합해 창작 통제권을 유지하는 방식을 시연합니다.

4. **Vite의 Rust 재작성과 검증 피드백 루프**
