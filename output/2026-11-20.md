2. **시험은 왜 있는가, 그리고 공정성**
   - 시험이 더 이상 아무것도 확인해 주지 못하는 상황이므로, 이제는 AI에게 일을 잘 맡기고 결과를 검증·이해하는 능력을 시험해야 한다고 주장합니다.
   - 수능에서 모두가 AI를 쓰면 공평한지, 같은 모델·비용·기기까지 맞춰야 하는지 묻고, 여러 번 응시하고 에세이와 과외 활동도 보는 미국 SAT와 비교합니다.

   - 컨닝을 옹호하는 것은 아니며, 처음부터 AI를 옆에 두고 보는 시험이 당연해질 것이라고 봅니다. Meta도 일부 지원자에게 AI를 쓰는 코딩 면접을 도입했습니다.

   - 좋은 질문은 목적, 지금 아는 것과 해본 것, 막힌 곳, 원하는 답의 모양을 담아야 하고, 에이전트에게 거꾸로 질문해 달라고 하는 소크라테스식 공부도 권합니다.

5. **AI 시대에 필요한 두 가지 경험**

## [I tested Claude Code's Code Mode: Before vs. After running the same tasks](https://www.youtube.com/watch?v=RoxXIszN-ds)

**한 줄 인사이트**
💡 Code Mode를 켜고 같은 작업을 12번 돌렸더니 답은 그대로인데 읽은 토큰은 47%, 소요 시간은 3분의 1 이상 줄었습니다.

**핵심 요약**
Claude Code 채널 운영자가 Cloudflare·Anthropic·Datadog가 내세운 99% 수준의 토큰 절감이 실제 Claude Code에서도 통하는지 직접 확인해 봅니다. 먼저 수치가 무엇을 측정한 것인지 짚고, 켜는 방법과 3가지 읽기 전용 과제 실험 결과, 그리고 어떤 사람에게 맞는지를 경험 순서대로 풀어갑니다.

1. **토큰이 새는 지점과 Code Mode의 원리**
   - 작업을 맡기기 전에 이미 약 57,000 토큰이 읽히는 점을 문제로 짚습니다.
   - Code Mode는 도구를 하나씩 호출하는 대신 AI가 코드를 작성해 도구를 호출하게 하는 방식으로, 2025년 11월 Claude Code에 실험 기능으로 도입되었습니다.

2. **99% 수치의 실체**
   - Cloudflare 99.9%, Anthropic 98.7%, Datadog 73%는 각 회사가 자체 환경에서 측정한 값입니다.
   - 세 수치 모두 Claude Code의 Code Mode로 측정한 결과가 아니라는 점을 분명히 합니다.

3. **켜는 방법과 제약**
   - claude update로 2.1.323 이상으로 올린 뒤 환경변수 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1을 설정해 실행하고, 첫 실행 시 안내에 yes로 답합니다.
   - 터미널 대화형 세션에서만 작동하며, 켜 두면 원격 제어, Chrome 연동, 컴퓨터 조작은 쓸 수 없습니다.

4. **직접 실험한 결과**
   - 연결된 도구가 많은 환경(Claude Code 2.1.329, Opus 5.5)에서 읽기 전용 과제 3개를 켠 상태와 끈 상태로 각각 2번씩 실행했습니다.
   - 답은 같았고 읽은 토큰은 47%, 시간은 3분의 1 이상 줄었으며, 결과는 도구와 작업에 따라 달라지므로 자주 하는 작업으로 직접 비교해 보라고 권합니다.

## [Engineer Your Coding Agents Like Any Other System — Zach Lloyd, Warp](https://www.youtube.com/watch?v=0LeT996Hz3E)

**한 줄 인사이트**
💡 코딩 에이전트를 로컬에서 하나씩 프롬프트하는 방식은 한계가 분명하며, 코드로 정의하고 측정·개선하는 폐쇄 루프형 "소프트웨어 팩토리"로 전환해야 처리량·비용·보안을 관리할 수 있다는 주장이다.

**핵심 요약**
Google Docs 엔지니어링 리드 출신인 Warp의 창업자 겸 CEO Zach Lloyd가, 대부분의 개발자가 아직 로컬에서 에이전트를 하나씩 다루는 현실에서 출발해 클라우드 에이전트를 시스템처럼 엔지니어링하자고 제안한다. 소프트웨어 팩토리의 정의와 인프라 스택을 설명한 뒤, 라이브 데모로 팀 뷰, 온라인 평가, 자기 개선 흐름을 보여준다.

1. **로컬 에이전트 방식의 한계**
   - 대부분의 개발자는 여전히 코딩 에이전트를 로컬에서 한 번에 하나씩 프롬프트하며, 이 방식은 처리량에 상한이 있다.
   - 이런 구조에서는 비용, 보안, 거버넌스를 관리하기도 어렵다.

2. **소프트웨어 팩토리의 정의**
   - 소프트웨어 팩토리는 코드로 정의되고, 클라우드 코딩 에이전트를 지속적으로 측정·개선하는 폐쇄 루프 시스템이다.
   - 모든 것을 측정하는 것이 핵심이며, 에이전트 실행 기록이 개선의 기반이 된다.

3. **팩토리 인프라 스택**
   - 구성 요소는 코드로 된 팩토리, 기록되는 에이전트 실행, 샌드박스 컴퓨트, 교체 가능한 모델과 하네스, 오케스트레이션이다.
   - 모델과 하네스를 바꿔 끼울 수 있게 해 특정 벤더에 묶이지 않도록 한다.

4. **데모: 관찰, 평가, 자기 개선**
   - 모든 에이전트를 실시간으로 보는 팀 뷰에서 처리량, 비용, 온라인 평가(online evals)를 확인한다.
   - 에이전트가 PR을 통해 스스로 개선하고, 자신의 데이터로 벤치마크를 돌려 모델과 하네스를 비교한다.

윤자동이 Claude Code만으로 영상을 편집하는 유튜버 동테크를 게스트로 초대해, "알아서 해줘"식 지시가 왜 어색한 결과로 이어지는지 짚는다. 두 사람은 지침서가 필요한 이유부터 짧게 쓰는 요령, 프레임 레퍼런스, 자막 규칙, 소재 검색까지 단계별로 풀고, 마지막에 "딱깍" 방식의 한계와 해법을 실제 사례로 정리한다.

1. **지침서(MD 파일)가 필요한 이유**
   - 동테크는 편집 프로그램을 쓰지 않고 Claude Code로만 편집하는 유튜버로, 당일 만든 예시 3개를 보여 준다.
   - 지침 없이 "알아서 해줘"만 던지면 결과가 어색해지므로 작업 기준을 담은 지침서가 필요하다.

2. **지침은 길게 말고 짧게**
   - 길고 상세한 매뉴얼이 능사가 아니며, 지침은 짧게 유지하라고 조언한다.
   - 영상에서는 이를 "신라면보다 매운" 짧은 지침이라는 표현으로 설명한다.

3. **1초 30프레임을 한 장의 레퍼런스로**
   - 1초 분량의 프레임 30장을 하나의 레퍼런스 이미지로 묶어 AI에게 전달하는 방식을 제안한다.
   - 이렇게 프레임 단위로 참고시키면 AI가 영상 흐름을 더 정확히 파악한다.

4. **자막 "밤티"와 숫자 가이드라인**
   - AI 자막이 엉뚱한 곳에서 끊기는 문제는 글자 수가 아니라 문법 단위로 끊도록 지시해 해결한다.
   - 숫자 표기에도 별도 가이드라인을 두어 일관성을 확보한다.

5. **소재 검색 가이드와 "딱깍"의 한계**
   - 소재를 찾는 과정에도 가이드라인을 적용해 검색 품질을 높일 수 있다.
   - 마지막으로 "딱깍" 한 번에 끝내려는 방식의 한계와 그 해결책을 실제 사례로 정리한다.
