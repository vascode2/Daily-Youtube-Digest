## [ACP: The Universal Remote Control for AI Agents — Alex Hancock, Block](https://www.youtube.com/watch?v=YkNulwcc5jk)

**한 줄 인사이트**
💡 AI 에이전트 생태계의 파편화를 해결하기 위해 MCP에 이어 클라이언트와 하네스를 연결하는 표준 프로토콜인 ACP(Agent Client Protocol) 도입이 시급합니다.

**핵심 요약**
Block의 소프트웨어 엔지니어인 알렉스 핸콕(Alex Hancock)은 현재 AI 에이전트 하네스들이 각기 다른 맞춤형 인터페이스를 사용하여 생태계가 파편화되어 있다고 지적합니다. 그는 에이전트가 외부 도구와 소통하는 표준인 MCP처럼, 클라이언트 소프트웨어가 하네스에 작업을 지시하고 업데이트를 받는 표준 프로토콜로 ACP(Agent Client Protocol)를 제안합니다. 궁극적으로 클라이언트, 하네스, 도구, 모델의 네 가지 레이어가 완전히 독립적으로 분리되어 작동하는 유연한 에이전트 스택의 미래를 제시합니다.

1. **맞춤형 인터페이스로 인한 에이전트 하네스의 파편화 문제**
   - 현재 대부분의 에이전트 하네스는 독자적인 인터페이스를 제공하여, 최악의 경우 단 하나의 애플리케이션만 해당 하네스를 제어할 수 있는 비효율성이 발생합니다.
   - 이는 마치 웹사이트마다 서로 다른 브라우저를 사용해야 하는 것과 같으며, 개발자들이 매번 새로운 클라이언트를 구축해야 하는 문제를 야기합니다.

2. **에이전트 클라이언트 프로토콜(ACP)의 등장 배경과 작동 방식**
   - ACP는 Zed와 JetBrains 팀이 모든 하네스를 구동할 수 있는 단일 고품질 에디터 클라이언트를 원했던 요구에서 출발한 JSON RPC 기반 프로토콜입니다.
   - 이 프로토콜은 세션 관리, 사용자 메시지 전달, 도구 호출 알림, 권한 요청 등을 처리하며 언더스코어(_) 접두사를 통한 확장성을 지원합니다.

3. **동일한 Goose 에이전트를 구동하는 이종 클라이언트 데모**
   - 핸콕은 오픈소스 에이전트 하네스인 Goose를 에디터 클라이언트인 Zed와 Poolside의 터미널 클라이언트가 동시에 구동하는 모습을 시연합니다.
   - 이를 통해 클라이언트 표준화가 이루어지면 개발자가 단 하룻밤 만에 새로운 클라이언트를 구축하여 기존 에이전트를 제어할 수 있음을 증명합니다.

4. **4가지 레이어로 완전히 독립 분리되는 에이전트 스택**
   - 원격 HTTP 및 웹소켓 전송 사양을 추가함으로써 클라이언트, 하네스, 도구(MCP), 모델의 네 가지 구성 요소가 완전히 독립적인 위치에 배치될 수 있습니다.
   - 이러한 디커플링은 클라이언트 시장의 경쟁을 유도하여 궁극적으로 최종 사용자의 경험(UX) 수준을 크게 끌어올릴 것으로 기대됩니다.

## [MCP 앱: 모델에게는 데이터를, 사용자에게는 UI를 제공하기 — Dustin Mihalik, Indeed](https://www.youtube.com/watch?v=lbaXnx0KLA8)

   - 텍스트 응답만으로는 브랜드 노출이 어렵고 호스트 채팅 앱에서 외부 링크를 연결하는 작업에 상당한 평가 시간이 소요된다.

3. **두 번째 규칙: 데이터 처리와 UI 렌더링을 분리하기**

   - 사용자가 위젯에서 상호작용할 때 발생한 이벤트 역시 모델 맥락에 반영되어야 모델이 어떤 작업을 열었는지 정확히 인지할 수 있다.

2. **모델의 캔버스 독해와 에이전트 스타터 키트**
   - 모델이 스크린샷과 기본 JSON 데이터를 함께 읽고 캔버스를 이해할 수 있도록 설계하는 것부터 에이전트 공간 학습이 시작됩니다.
