   - 리뷰는 팀 내 지식 공유, 멘토링, 아키텍처 피드백, 그리고 신규 팀원 온보딩을 위한 핵심적인 소통 창구였습니다.

## [Security Firewall for Agents — Ryan Dahl, Deno](https://www.youtube.com/watch?v=MkRYPFIMCSA)

**한 줄 인사이트**
💡 AI 에이전트의 보안은 모델의 자체적인 통제력에 의존해서는 안 되며, 네트워크 하위 레이어에서 모든 트래픽을 감시하고 차단하는 독립적인 프록시 방화벽을 통해 구축해야 합니다.

**핵심 요약**
Deno의 창립자 Ryan Dahl은 프로덕션 환경에 직접 접근하는 AI 에이전트가 프롬프트 주입 공격을 받았을 때 발생할 수 있는 치명적인 보안 위협을 지적합니다. 그는 LLM의 거절 능력에 의존하는 기존 방식의 한계를 규명하고, 에이전트 외부에서 모든 네트워크 패킷을 검사하는 새로운 오픈소스 보안 솔루션을 대안으로 제시합니다. 이를 통해 에이전트가 신뢰할 수 없는 소프트웨어라는 전제하에 시스템을 안전하게 보호하는 구체적인 아키텍처를 설명합니다.

1. **LLM 자체 보안 및 MCP 도구 권한의 한계**
   - Claude Opus 같은 강력한 모델도 프롬프트 주입 공격을 받으면 프로덕션 데이터베이스의 테이블을 삭제하라는 명령을 수행할 위험이 존재합니다.
   - 단순한 HTTP 규칙이나 MCP(Model Context Protocol) 도구 정의만으로는 에이전트가 EKS 엔드포인트를 통해 psql 서브프로세스를 실행하고 터널링하는 등의 우회 경로를 감지할 수 없습니다.

2. **오픈소스 프록시 방화벽 Claw Patrol의 도입**
   - Deno는 에이전트 앞단에서 HTTP 레이어 아래의 모든 바이트를 파싱하고 감시하는 MIT 라이선스 기반의 오픈소스 프록시인 Claw Patrol을 개발했습니다.
   - 이 프록시는 쿠키, OAuth, AWS SigV4 등의 인증 자격 증명을 직접 보유하여 에이전트가 민감한 자격 증명 정보에 직접 접근하지 못하도록 원천 차단합니다.

3. **HCL 기반 규칙 설정과 다중 승인 시스템**
   - 보안 규칙은 Terraform에서 사용하는 HCL 언어로 작성되어 Git에 체크인되며, Deno의 경우 약 1,000라인에 달하는 규칙 파일로 단위 테스트를 수행합니다.
   - 에이전트의 특정 행동이 감지되면 LLM 판사(Judge)나 Slack을 통한 인간의 승인 단계를 거치도록 라우팅하여 이중 안전장치를 제공합니다.

4. **프로토콜 수준에서의 위험 명령 차단 데모**
   - 데모 시연에서는 Codex 모델이 사용자 테이블을 삭제하라는 명령을 그대로 수행하려 할 때, Claw Patrol이 Postgres 와이어 프로토콜 수준에서 이를 감지하고 즉각 차단하는 모습을 보여줍니다.
   - 이 시스템은 Tailscale이나 WireGuard 위에서 동작할 수 있어, 에이전트가 스스로를 통제할 수 없다는 전제하에 완벽한 외부 통제를 실현합니다.

## [Context Engineering in 2026 — Louis-François Bouchard, Omar Solano & Samridhi Vaid, Towards AI](https://www.youtube.com/watch?v=WP3hjUXd918)

**한 줄 인사이트**
💡 프롬프트 캐싱 기술의 발전으로 인해 컨텍스트를 압축하는 것보다 원본 히스토리를 그대로 유지하는 것이 비용, 지연 시간, 정보 복원력 측면 모두에서 훨씬 더 유리합니다.

**핵심 요약**
Towards AI의 Louis-François Bouchard, Omar Solano, Samridhi Vaid는 자체 개발한 오픈소스 AI 튜터 프로젝트를 통해 다양한 컨텍스트 압축 기술의 실효성을 검증합니다. 이들은 무조건적인 컨텍스트 요약이 오히려 프롬프트 캐싱을 무력화하여 비용을 증가시키고 정보 검색 성능을 떨어뜨린다고 주장하며, 하드웨어 제약 조건을 먼저 정의할 것을 제안합니다. 실험 결과, 컨텍스트에 아무런 조작을 가하지 않고 그대로 유지하는 것이 비용과 속도, 정확도 모두에서 가장 우수한 성적을 거두었습니다.

1. **프롬프트 캐싱과 컨텍스트 압축의 역설**
   - 컨텍스트를 요약하거나 압축하면 프롬프트 캐싱이 무효화되어, API 비용이 최대 50배까지 저렴한 캐시 토큰의 이점을 누리지 못하고 오히려 더 많은 비용을 지불하게 됩니다.
   - 전체 토큰의 97%가 캐시에서 제공되는 환경에서는 컨텍스트 압축 기술이 비용 효율성을 갖추기 위해 최소 50배 이상 크기를 줄여야만 수지타산이 맞습니다.
2. **정보 복원력 및 검색 정확도 비교**
   - 대화 히스토리를 요약 없이 그대로 유지했을 때는 구체적인 세부 정보를 95% 확률로 복원한 반면, 요약본을 사용했을 때는 복원율이 32%로 급감했습니다.
   - 독특한 사실 정보들은 컨텍스트가 800,000 토큰까지 늘어나도 정보의 열화 없이 생존하여 모델이 정확하게 찾아낼 수 있었습니다.
3. **지식 베이스 브라우징 도구의 성능 한계**
   - 연구진이 구축한 지식 베이스 브라우징 도구는 정보 복원력(Recall) 측면에서 기존 방식과 동일한 성능을 보였으나, 작동 속도는 50% 더 느려지는 결과를 초래했습니다.
   - 400,000 토큰 깊이에 묻힌 사실을 검색할 때 밀집 검색(Dense Retrieval)은 복원율이 0%로 떨어졌지만, 전통적인 BM25 알고리즘은 매번 정확하게 정보를 찾아냈습니다.
4. **로컬 환경의 제약과 컨텍스트 설계 규칙**
   - 로컬 환경에서 32k 컨텍스트 창 제한이 걸려 있는 하드웨어의 경우, 모델의 파라미터 크기가 커지더라도 컨텍스트 창 자체가 늘어나지 않으므로 무조건적인 히스토리 보존은 불가능합니다.
   - 개발자는 기본값으로 컨텍스트 압축을 수행하기 전에, 시스템이 직면한 실제 하드웨어 및 비용 제약 조건이 무엇인지 명확히 정의하고 이에 맞춰 최적화해야 합니다.
