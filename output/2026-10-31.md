4. **기억의 일생: 쓰고, 정리하고, 고치기**

## [Your AI Agent Wants Your Data. Here's How to Lock It Down - Jeff Smith, Oracle](https://www.youtube.com/watch?v=LnQce-eHm8k)

**한 줄 인사이트**
💡 자연어-SQL은 쿼리가 오류 없이 실행되면서도 엉뚱한 데이터를 돌려줄 수 있으므로, 검증된 리포트를 도구로 제공하고 DB 단에서 행 단위 보안을 강제해야 에이전트를 안전하게 쓸 수 있다.

**핵심 요약**
25년간 Oracle에서 데이터베이스 도구를 만들어 온 Jeff Smith가 에이전트와 데이터베이스를 안전하게 연결하는 방법을 설명합니다. 먼저 에이전트에 DB 접근이 필요한 이유와 자연어-SQL의 위험을 짚고, 이어 Oracle MCP 서버로 구현하는 세 가지 활용 사례와 보안 모델을 차례로 보여줍니다.

1. **자연어-SQL의 위험과 리포트의 도구화**
   - 자연어로 만든 SQL은 문법적으로 문제없이 실행되어도 잘못된 데이터를 반환할 수 있어, 임의 SQL 생성은 위험하다고 지적합니다.
   - 대안으로 팀이 검증한 리포트를 MCP 도구로 노출해 에이전트가 리포트를 조회(list)하고 실행(execute)하도록 합니다.

2. **읽기 전용 스탠바이를 활용한 성능 튜닝**
   - 성능 튜닝 사례에서는 에이전트를 운영 DB가 아닌 읽기 전용 스탠바이(standby)에 연결합니다.
   - 이렇게 하면 에이전트가 쿼리를 분석하고 시험해도 운영 환경에 영향을 주지 않습니다.

3. **에이전트를 위한 스키마 문서화**
   - 스키마에 주석(annotation)을 달아 에이전트가 데이터 사전을 무차별 탐색(brute-force)하지 않고 의미를 바로 이해하게 합니다.
   - 이는 불필요한 탐색 쿼리를 줄이고 정확한 쿼리 작성을 돕는 방식입니다.

4. **누가 요청하는가: 딥 데이터 보안**
   - Oracle의 deep data security는 사용자가 볼 권한이 없는 행을 결과가 에이전트에 도달하기 전에 제거합니다.
   - 따라서 보안이 프롬프트가 아니라 데이터베이스 수준에서 요청자 기준으로 적용됩니다.

**한 줄 인사이트**
💡 설문에서 78%가 원한다고 답한 AI 사진 피드백 기능을 실제로 쓴 사용자는 10~15%에 불과했고, A/B 테스트의 "승리"만으로는 비용·모델·규제 같은 현실 변수를 읽을 수 없습니다.

**핵심 요약**
Bumble의 프로덕트 매니저 Supriya Subudhi가 월 2,000만 명 이상이 쓰는 데이팅 앱에서 AI 사진 피드백 기능을 A/B 테스트하며 얻은 다섯 가지 교훈을 공유합니다. 사용자 요구와 실제 사용의 괴리에서 시작해 평균 지표의 함정, 비용, 모델 의존성, 규제 문제로 이어지며 "성공"이라는 판단이 얼마나 불완전한지 보여줍니다. 마지막에는 AI 테스트를 승리로 선언하기 전에 던져야 할 다섯 가지 질문을 제시합니다.

1. **사용자는 요청하지만 실제로는 쓰지 않는다**
   - 설문에서 78%가 사진 피드백을 원한다고 답했지만 실제 사용률은 10~15%에 그쳤습니다.
   - 말로 표현한 수요와 실제 행동 사이의 격차를 먼저 확인해야 합니다.

2. **평균적인 승리가 꼬리 구간을 가린다**
   - 전체 평균 지표는 좋아 보였지만, 웃고 있는 사람에게 더 웃으라고 조언하는 등 이상한 출력이 숨어 있었습니다.
   - 평균만 보면 소수의 나쁜 경험이 보이지 않습니다.

3. **대시보드는 초록, 청구서는 빨강**
   - 성능이 가장 좋은 모델은 비용이 약 10배 높았습니다.
   - 지표상 성공이 곧 수익성 있는 성공은 아니라는 점을 강조합니다.

4. **성과는 모델에서 나왔다**
   - 더 저렴한 모델로 바꾸자 효과도 함께 줄었습니다.
   - 결과가 기능 설계보다 특정 모델 성능에 크게 좌우되었다는 의미입니다.

5. **글로벌 출시가 불가능할 수 있다**
   - 규제 때문에 이 기능은 미국 밖으로 출시할 수 없었습니다.
   - 테스트에서 이겨도 확장 가능성은 별개의 문제입니다.
