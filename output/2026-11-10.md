## [Google's Surprise Launch of Massive TPU 8i Max and 8tx: Accelerating In-House Chip Development to...](https://www.youtube.com/watch?v=xYoJ1kePj9c)

**한 줄 인사이트**
💡 TPU 8i Max의 가치는 연산력과 HBM 대역폭 증가에 더해, 메모리 용량과 전송 속도의 차이가 실제 AI 서비스의 속도와 비용으로 이어지는 방식에서 판가름 난다.

**핵심 요약**
Google이 두 개의 기존 TPU 칩을 하나의 패키지로 묶은 TPU 8i Max와 보안 기능을 강화한 TPU 8tx를 공개했습니다. 영상은 메모리 용량과 전송 속도가 서로 다른 문제라는 점에서 출발해, 이 차이가 AI 서비스의 속도와 비용에 어떻게 반영되는지 공개된 TPU·GPU 비교 자료로 따져 봅니다. 마지막에는 Anthropic처럼 여러 AI 칩을 함께 쓰는 고객 사례를 근거로 TPU가 기존 GPU와 경쟁할 가능성을 짚습니다.

1. **TPU 8i Max와 8tx의 구성**
   - 8i Max는 기존 TPU 칩 두 개를 한 패키지로 결합한 제품입니다. 연산력과 HBM 대역폭을 함께 높여 AI에 필요한 데이터를 더 빠르게 공급하도록 구성되었습니다.
   - 8tx는 보안 기능이 강화된 모델입니다.

2. **메모리 용량과 전송 속도는 별개의 문제**
   - 메모리에 얼마나 많은 데이터를 담을 수 있는지와 얼마나 빨리 옮길 수 있는지는 서로 다른 문제입니다. 영상은 이 차이가 실제 AI 서비스의 속도와 비용에 어떻게 이어지는지 살펴봅니다.

3. **운영 낭비를 줄이는 소프트웨어**
   - TPU Sync는 이전에 처리한 데이터의 KV 캐시를 재사용하고 서버 메모리로 옮겨 HBM 공간을 활용하는 소프트웨어입니다.
   - NVIDIA도 Dynamo로 비슷한 운영 낭비를 줄이고 있습니다.

4. **비용 비교와 도입 조건**
   - 공개된 TPU·GPU 비교 자료를 보면 비용 평가는 모델, 수치 형식, 품질, 응답 속도에 따라 달라집니다. 신형 8i Max의 사양과 이전 세대 장비의 테스트 결과는 구분해서 봐야 합니다.
   - 개발 도구 지원과 연산 중 데이터 보호는 TPU를 실서비스에 도입하는 고객에게 중요한 조건입니다. 여러 종류의 AI 칩을 함께 쓰는 Anthropic 사례를 근거로, 기존 GPU가 빠지기 전에 다음 서버 주문부터 경쟁이 나타날 가능성을 따져 봅니다.

## [Your Agent Doesn't Need an LLM for Every Decision - Raymond Weitekamp, OpenProse](https://www.youtube.com/watch?v=hFNbPmzzcEs)

**한 줄 인사이트**
💡 에이전트의 모든 판단을 LLM에 맡길 필요 없이, 빠른 분류기인 System One 결정 모델에 재귀 구조를 적용하면 워크플로가 훨씬 효율적이 된다.

**핵심 요약**
OpenProse의 Raymond Weitekamp는 LLM의 강력한 하네스 패턴으로 자리 잡은 재귀 언어 모델(Recursive Language Models)의 발상을 결정 모델에 그대로 적용할 수 있다고 주장한다. 그는 이를 Recursive Decision Models로 정리하고, 코딩 에이전트·정보 검색·컴퓨터 사용 워크플로에 적용하는 방법을 보여준 뒤, 실시간 인터페이스 비전과 새 에이전트 oSo를 소개한다.

1. **재귀 언어 모델에서 결정 모델로**
   - 재귀 언어 모델은 LLM을 감싸는 강력한 하네스 패턴으로 자리 잡았다.
   - 발표자는 같은 아이디어를 System One 모델, 즉 빠른 분류기인 결정 모델에도 적용할 수 있다고 본다.

2. **Recursive Decision Models (RDM)**
   - 매 판단마다 LLM을 호출하는 대신 빠른 분류기를 재귀적으로 활용해 워크플로를 훨씬 효율적으로 만드는 접근이다.
   - 적용 분야는 코딩 에이전트, 정보 검색, 컴퓨터 사용(computer use)이며, 구현은 recursivedecisionmodels.com과 GitHub의 rawwerks/rdm에 공개되어 있다.

3. **Operating System One 비전**
   - 발표자는 System One 모델을 기반으로 하는 실시간 인터페이스의 미래상을 Operating System One이라는 이름으로 제시한다.

4. **oSo: 컴퓨터 사용 결정 에이전트**
   - 새로운 컴퓨터 사용 결정 에이전트 oSo를 미리 선보이며, 이 접근을 실제 제품 형태로 확장하는 방향을 보여준다.
